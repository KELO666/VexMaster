# VEX 赛程管理助手 (VEX Schedule Master) - 项目交接文档

## 1. 项目概况
* **项目名称**：VEX 赛程管理助手
* **项目背景**：为 VEX 机器人竞赛量身定制的移动端效率工具。旨在解决赛场环境下网络不稳定、纸质对阵表查阅繁琐、多赛区统筹困难等痛点。
* **主要目标用户**：VEX 机器人教练、赛队队员及俱乐部管理者。
* **核心价值**：纯本地化运行、离线可用、多端适配、一键生成赛程海报。

## 2. 技术架构 (无后端纯前端架构)
本项目采用 **“100% 纯前端 + 本地化存储”** 方案，无任何服务器数据库依赖，确保在赛场恶劣网络环境下绝不宕机。

* **核心语言**：原生 HTML5 + CSS3 + JavaScript (无重度框架，保障极致加载速度)。
* **数据存储**：HTML5 `LocalStorage` (赛程数据、比分数据、队伍配置永久保存在用户设备本地)。
* **第三方核心依赖** (均通过极速 CDN 引入)：
  * `pdf.js` (v2.6.347)：用于纯前端解析对阵表 PDF 文本。
  * `html2canvas` (v1.4.1)：用于将 DOM 元素渲染为分享海报。
* **CDN 节点**：选用 360 极速节点 (`lib.baomitu.com`)，以彻底解决苹果 iOS 系统默认拦截部分海外/不规范 CDN 节点导致“组件加载失败”的问题。

## 3. 核心功能清单
1. **多格式 PDF 高速解析**：支持在微信中直接保存赛事官方下发的 PDF 对阵表，支持多次追加导入不同赛区的对阵表。
2. **AI 智能提取**：自动从 PDF 文件名或内容中提取“赛区/组别”(Division)，并解析出 `Q编号`、`场地`、`时间`、`红蓝方联盟`。
3. **单队视图与海报生成**：输入己方队伍号，自动过滤出该队的所有比赛。提供完赛比分记录，并可一键生成带有红蓝方标识的战报海报。
4. **大师总表 (Master Timeline)**：统筹整个俱乐部的多支队伍。将所有关注队伍的比赛按时间流严格排序，支持“隐藏已赛”、自动标记“NOW (当前待赛)”，并支持按赛区筛选。

## 4. 双端分支及部署规范（核心交接点）
由于 Android 和 iOS 系统的生态差异极大，本项目采用**“主干隔离，双线分支”**的维护模式。

### 📁 分支 A：Android 原生版 (`VEX_Master_Android` 目录)
* **定位**：通过 HBuilderX 封装的 Native App。
* **特性**：调用了 H5+ 底层 API（如直接将海报存入系统相册）。
* **部署与打包流程**：
  1. 使用 **HBuilderX** 打开 `VEX_Master_Android` 文件夹。
  2. 修改核心代码 `index.html`。
  3. 双击 `manifest.json`，在“基础配置”中确认 App 名称，在“App图标配置”中一键生成 1024x1024 的图标。
  4. 顶部菜单栏点击：`发行` -> `原生App-云打包`。
  5. 勾选 Android，使用公共测试证书，取消所有广告/渠道包选项。
  6. 打包完成后，在项目的 `unpackage/release/apk/` 目录下提取 `.apk` 文件。

### 📁 分支 B：iOS / Web 通用版 (`VexMaster` 目录)
* **定位**：基于 PWA (Progressive Web App) 架构的纯 Web 应用。
* **特性**：为了适应苹果沙盒机制，移除了相册自动保存代码，改为“渲染图片后引导用户长按保存”。加入了 iOS 专属 Meta 标签（隐藏地址栏、适配刘海屏及底部小黑条 `env(safe-area-inset-bottom)`）。
* **部署与更新流程 (GitHub CI/CD)**：
  1. 此分支代码与 GitHub 仓库直接绑定。
  2. 使用 HBuilderX 或任何编辑器修改 `VexMaster` 目录下的 `index.html`。
  3. 打开 **GitHub Desktop**，软件会自动检测到更改。
  4. 填写 Commit 描述，点击 `Commit to main`，然后点击 `Push origin`。
  5. GitHub Pages 会在 1 分钟内自动完成全球部署。
  6. **用户端更新**：教练只需在 Safari 中打开网页 `https://<your-username>.github.io/<repo-name>/` -> 点击“分享” -> **“添加到主屏幕”**。后续每次 Push 更新，用户杀掉后台重开即可自动热更。

## 5. 历史踩坑与关键技术决策
1. **iOS 解析引擎白屏/加载失败**：
   * *问题*：新款 pdf.js 使用了高级语法，导致带 Home 键的老款 iPad 浏览器内核直接崩溃；同时 iCloud 专用代理会拦截部分国内静态节点。
   * *决策*：将引擎主动降级为被誉为兼容之王的 `v2.6.347` 稳定版，并强制切换为 `baomitu` 节点。
2. **iOS 软键盘弹跳留白**：
   * *问题*：iPhone 输入比分收起键盘后，网页底部留白，DOM 无法自动回弹归位。
   * *决策*：在 `body` 挂载 `focusout` 监听器，加入 `window.scrollTo(0, document.body.scrollTop)` 强制重绘规避。
3. **文件读取权限**：
   * *决策*：弃用传统的绝对路径读取。统一采用 W3C 标准的 `<input type="file">`，无论安卓还是 iOS，均通过系统原生文件管理器流式读取，完美穿透微信沙盒限制。

## 6. 后续接手人维护建议
1. **切勿合并双端代码**：Android 的 H5+ 专属代码（如 `plus.gallery.save`）在 iOS 浏览器环境会直接报错阻断运行，请严格遵守 `VEX_Master_Android` 与 `VexMaster` (iOS) 分离维护的原则。
2. **真·离线化改造 (V2.0 规划)**：目前解析和生成海报仍依赖首次加载时的外网 CDN。若要应对极端的“无信号地下体育馆”，建议将 `pdf.min.js`、`pdf.worker.min.js` 和 `html2canvas.min.js` 三个文件物理下载至项目目录进行本地引入。
3. **数据备份导出功能**：LocalStorage 存在被用户在系统设置中误清空的风险，建议在后续迭代中加入“导出 JSON 备份”至系统剪贴板的功能。
